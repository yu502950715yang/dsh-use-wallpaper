# v0.8.1 可见缺口修复设计（spec）

> 日期：2026-10-20 ｜ 目标版本：`0.8.1`（patch） ｜ 依据：[本机壁纸功能缺口审计](../../2026-10-20-library-feature-gap-audit.md) + [复核报告](../../../research/audit-2026-10-20/verification.md)
> 范围：从审计报告 P0/P1 中挑选「可见差异明确、改动边界清晰、不改变架构」的 7 项缺口；其余缺口进 v0.9.0 路线图。

## 1. 目标与非目标

**目标**：让 30 张「缺功能」壁纸中一批高频、可见的差异在本机获得修复，且对现有 13 张「不缺口」壁纸零回归（`e2e:compare` 判据：最大差 ≤ 1 且差≥2 像素为 0）。

| 编号 | 缺口 | 命中壁纸 | 修复后可见变化 |
|---|---|---|---|
| F3 | text 对象的 effects 不挂链（静默丢弃） | 7 张 | 时钟/日期/时间文字获得作者挂的 blurprecise/vhs/waterwaves |
| F4 | sound 对象只全量 loop：volume/playbackmode 不消费、多文件同时播 | 5 张 | 背景音乐音量还原；多首不再叠播（按 WE 语义选一首） |
| F7 | 粒子顶层 `starttime` 不解析 | 25 张 | 起播相位与桌面一致（闪光/流星/余烬类可感知） |
| F8 | 壁纸级 `general.bloom*` 未实现 | 3 张 | 血月/赛博朋克/千束的亮部获得作者设定强度的 bloom |
| F13 | image 精灵表按整表渲染 | 1 张 | 日夜切换图标显示当前帧而非整张帧表 |
| F15 | `general.clearcolor` 解析但无消费（清屏恒黑） | 2 张 | 纯文本场景整屏底色还原（#111418 / 深棕） |
| F21 | `instanceoverride` 的 `{user,value}` 包装未解包 | 1 张 | additive 雪层不再变黑不可见 |

**非目标（明确不做，进 v0.9.0）**：F1 子粒子、F2 util 后处理层、F5 用户属性扩展、F6 `_rt_` 帧快照、F9 粒子高级特性、F10 脚本交互链、F11 音频可视化、F12 text 布局字段、F14 `{script}`/`{animation}`、F16/F17 web/video 音频与属性、F18 全局 uniform、F19 puppet effects、F20 非 visible `{user}`。

## 2. 设计决策

### D1（F3）text 效果链：复用 image 的隔离路径

- `SceneTextObject` 增加 `effects?: unknown[]`（与 image/particle 同字段）；`scene-json.ts` 的 text 分支透传 `o.effects`。
- `object-range.ts:91` 删除 `if (obj.kind === 'text') continue;`，text 进入 `groupEffectsByObject`。
- `three-renderer.ts`：
  - `collectObjectEffectChains` 的收链来源改为 groupEffectsByObject（含 text）；
  - isolate 表新增 text 分支：世界尺寸 = `textLayers.get(id).size`（实测 canvas 布局）× |scale|；**RT 以布局 canvas 像素为源分辨率下限**（`isolatedRtSize(world, density, source=布局尺寸)`，text 不进 `fitIsolatedBudget`，与粒子一致）。**errata（热修 2026-10-20）**：初版按屏占位（`objectRtSize`）建 RT，小字号 text（`3660373677` Date/Clock 布局 917×214 / 489×214 → RT 仅 97×22 / 46×20）在效果链里先被降采样，`blurprecise` 1.3px 相对笔画过强、文字糊成一团；现与 image 的 source 口径同源（回归用例：`tests/three-renderer.test.ts` 的「text 隔离 RT 以布局像素为源分辨率下限」）；
  - text 对象与 image 共用 `player.addBackground({ ..., isolate })` 路径（player 的 text 分支已支持同一入口）。
- **边界**：隔离 RT 尺寸在装配期冻结。时钟文本跨分钟变宽时，合成 quad 仍按装配期尺寸采样（轻微拉伸/裁边）；仅在 text 尺寸变化超过 10% 时由 player 的 driver 更新路径触发 `resizeObjectRT`（本期不实现自动重建，记为已验收边界）。脚本驱动尺寸变化（F10 范畴）不做。

### D2（F4）sound 语义：结构化 sound 对象 + 选一首 + 音量

- `SceneDescription.sounds` 由 `string[]` 改为 `SceneSoundObject[]`：
  ```ts
  export interface SceneSoundObject {
    files: string[];                 // scene.json object.sound 数组（可能多文件）
    volume: number;                  // 0-1，缺省 1
    playbackmode: 'loop' | 'random' | 'single';
  }
  ```
- `scene-json.ts` 的 `collectSounds` 按对象收集（而不是只收集文件名），缺省 volume=1 / playbackmode='loop'。
- 播放语义（以 `research/open-wallpaper-engine` 的 SoundParser/播放逻辑为准，实现前先核对；参考实现缺失时的回退口径写在任务里）：
  - `loop`：取 `files[0]` 循环（OWE 实际为多文件轮播，本期不实现）；
  - `random`：装配时从 files 随机选一首循环（OWE 播完重随机，本期不实现）；
  - `single`：**随机选一首**播放一次（不 loop；按 OWE `SelectStartIndex` 随机起点，不是 `files[0]`）。
- `audio-input.playWallpaperSound(url, analyzer, opts?: { volume?: number; loop?: boolean })`：新增 GainNode（`gain.value = volume`）插在 source → analyser 之间；`loop` 由 opts 控制。
- `three-renderer.startAudio` 接收 `SceneSoundObject`：按语义选文件、传 volume/loop；`lastAudioSpec` 同类型。

### D3（F7）粒子 starttime：解析 + 预推进

- wasm `ParticleSpec` 增加 `starttime: f32`（顶层 `starttime`，缺省 0；`parse_particle_spec` 读取）。
- `SceneParticleSim` 增加 `advance_initial(seconds)`：以固定步长 `1/60`、上限 900 步循环调用 `update`（= 预推进 ≤15s；15s 是审计报告里本机最大 starttime）。
- `CpuParticleSim::new`：`sim.prewarm()` 之后调用 `sim.advance_initial(spec.starttime)`（顺序固定：prewarm 先建稳态，starttime 再前滚相位/存活状态）。
- **errata（实现后）**：实际步长为 `1/60/rate`（`update` 内部再乘 `rate`）⇒ 每步恒 **1/60 effect 秒**，900 步 = **15 effect-s**（与 `rate` 无关）；超限**静默截断、不 warn**。
- **判据**：`starttime=0` 的模拟输出与改动前逐字节一致（Rust 快照测试）；`starttime=2` 时 `sim.time ≈ 2` 且非空池。

### D4（F8）壁纸级 bloom：复用 GlowStage 管线 + 两级串联

- 新增 `src/client/bloom-stage.ts`：`createBloomStage(w, h, { strength, threshold })` = 对 `createGlowStage` 的薄封装（参数归一：strength 缺省 2、threshold 缺省 0.65；与 Glow 的缺省不同，不得共用缺省常量）。
- `glow-stage.ts` 的 `GlowStage.apply` 增加可选第 5 参 `outTarget?: THREE.WebGLRenderTarget | null`：composite pass 写入该 target（缺省 null = 画布），并在 `GlowStage` 接口声明。
- `threejs-player.ts`：
  - 新增 `bloomStage` / `setBloomStage(stage)`；
  - render 主路径：`bloom` 存在时先 `bloomStage.apply(renderer, scene, camera, undefined, bloomRT)`，再按原逻辑处理 glow（glow 存在则 `glowStage.apply(..., bloomRT)`，否则 composite 贴回）；无 bloom 时路径逐字节不变；
  - `renderSegmented` 末段同序：`bloom.apply(..., capture.target, bloomRT)` → `glow.apply(..., bloomRT)` 或 composite；
  - `resize()` 同步 `bloomStage.resize`；`dispose` 释放。
- `scene-json.ts`：解析 `general.bloom/bloomstrength/bloomthreshold` → `SceneDescription.bloom?: { strength: number; threshold: number }`（`bloom === true` 才产出）。
- **边界**：`general.hdr` 不实现（本机 0 命中）；壁纸 bloom 与用户 Glow 叠加顺序 = 先壁纸 bloom 后 Glow，两者独立开关。

### D5（F13）image 精灵表：材质 combos 消费 + 帧 UV

- `scene-assets.ts` 的 `resolveImageAssets` 额外读取 `material.passes[0].combos.spritesheet`，返回值增加 `spriteSheet: boolean`（向后兼容：返回对象扩展字段）。
- `three-renderer.ts` 的 image 装配：`spriteSheet` 为 true 时给 mesh 打标记（`backgroundTexture.userData.spritesheet = true` 或新增 `imageSprites` Map），交给 player。
- `threejs-player.ts` 的 image 分支：纹理有 `userData.sprite` 且标记为 spritesheet 时，按 `frames/cols/rows` 计算当前帧的 UV 子矩形并写入 mesh geometry 的 `uv`（每帧推进：`frame = floor(t * 帧率) % frames`，帧率缺省 1 帧/秒）；无脚本控制（`getTextureAnimation` 留 v0.9）。
- **errata（实现后）**：帧率固定 **1 fps**，TEXS 的 `frametime` **未解析**（WE image 材质也无 `sequencemultiplier`，spec 原写的「取 sequencemultiplier 若存在」不成立）；帧网格只取 TEXS 的 `frames` / `cols` / `rows`。
- **判据**：单测验证 UV 子矩形（frames=3 竖排 → 三组 UV）；e2e 用 3765967112 判据「图标区域不再包含 3 帧拼接纹理」（像素统计）。

### D6（F15）清屏色

- `SceneDescription.clearColor` 已解析；`threejs-player` 构造/装配时接收 `clearColor?: [number, number, number]`（加在 `SceneAssets` 或 player options，选择后者：`opts.clearColor`），`renderer.setClearColor(new THREE.Color(r/255, g/255, b/255), 1)`。
- **订正（实现后）**：真实 `general.clearcolor` 是 **0-1** 归一化值（本机 37 张全部 ≤1）；0-1 → 0-255 的归一化在 `parseSceneJson` 完成（max 分量 ≤1 ⇒ ×255），player 接口仍收 0-255。
- **订正（实现后）**：唯一装配点是 `threejs-player.ts` 的 `loadSceneToThree`（它自己 `parseSceneJson` 并持有 `desc.clearColor`）；`three-renderer.ts` 只把 sceneJson 交给它，未改。
- 段渲染路径（`threejs-player.ts:1158`）由硬编码 `0x000000` 改为「当前清屏色」（保存/恢复逻辑已有）。
- **判据**：单测 mock renderer 断言 `setClearColor` 调用值；e2e 用 2980088441 判据「渲染图角落像素 ≈ #111418（容差 ±8）」。

### D7（F21）instanceoverride 包装解包

- `scene-json.ts` 的 `serializeInstanceOverride`：递归归一化 `{user?, script?, value}` 包装（仅当对象含 `value` 且无其它数值字段时解包为 `value`），输出仍为 JSON 文本；wasm 侧不改。
- **判据**：单测（构造 scene.json 片段 + 2859263090 素材快照断言 `colorn` 为 `"1.000 1.000 1.000"` 而非对象）；wasm 冒烟测试确认 `parse_particle_override` 得到白色。

## 4. 测试与验收

1. **TDD**：每任务先写失败测试（jsdom/node 单测或 Rust `#[cfg(test)]`）。
2. **零回归**：渲染改动（F3/F8/F13/F15）必须跑 `e2e:compare`（before/after 对拍，判据：maxAbs≤1、差≥2 像素为 0）。
3. **新增像素判据**（`e2e:verify-v081`）：bloom 亮部 luma 增量、clearcolor 角落颜色、spritesheet 帧 UV。
4. **真机验收**（`TESTING.md` 增节，用户执行）：bloom 观感（2454403969/3790775478）、音效音量与多轨（2011060960/2597392171）、text 效果强度（3660373677/3814332254）、精灵表帧（3765967112）。

## 5. 风险与回退

| 风险 | 缓解 |
|---|---|
| text 隔离破坏共享场景路径（透明排序/视差） | `e2e:compare` 零回归 + 仅对有链 text 生效；无链路径逐字节不变 |
| bloom 两级串联影响 Glow/段渲染路径 | 无 bloom 时 `render()`/`renderSegmented()` 路径不变；有 bloom 分支单测覆盖调用顺序 |
| wasm starttime 预推进成本（10000 粒子 × 900 步） | 上限 900 步（15 effect-s）+ 实测构造耗时（`2897292240` 单对象约 155ms / 两个对象约 0.3s）；超限**静默截断（不 warn）** |
| spritesheet UV 影响普通 image | 仅在材质 `combos.spritesheet` 为真时启用；普通 image 路径不变 |
| sound 类型改动波及测试 | 类型一次性切换 + 所有调用点在同一任务内更新 |
