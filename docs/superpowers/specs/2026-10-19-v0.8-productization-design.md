> **日期**：2026-10-19

## 1. 背景与目标

竞品分析结论：本项目 scene 渲染深度/正确性是长板，但普通用户第一眼看到的产品面缺口是——scene 失败只剩预览图、没有轮播/上传/库管理/显示调节/视频兜底/属性面板。v0.8 只做「产品可用性」，不改渲染器语义。

**目标**：把 6 个 P0 缺口补到「可日常使用」，并保持零回归：scene 渲染路径语义、既有设置行为、永不白屏承诺均不变。

## 2. 范围

**做（6 项）**

| # | 功能 | 验收口径 |
|---|---|---|
| F1 | scene 多级降级链：实时渲染 → `.tex` 内嵌 MP4 → 抓帧 PNG → 作者预览图 → 空态 | 真实样本 `2911105183` / `3800645169`（含内嵌 MP4）；失败注入时可回退到对应层 |
| F2 | 视频编码兜底：解码失败/首帧超时 → 预览图 + 面板明确提示 | HEVC（Edge）不再停在黑背景；提示可见 |
| F3 | 显示效果面板：`overlayOpacity` / `blur*` / `kenBurns` 控件 + 图片/视频适配模式 | 改控件立即生效并持久化；面板与 README 一致 |
| F4 | 自动轮播：收藏优先/全库兜底、间隔、顺序、暂停联动、手动选择重置、硬失败本会话跳过 | 假时钟单测 + 面板状态正确 |
| F5 | 壁纸库最小产品化：搜索、类型筛选、收藏、隐藏/恢复、最近使用排序 | 纯前端；localStorage；面板测试 |
| F6 | 用户属性面板（v0.8 限定布尔可见性开关） | `project.json general.properties` × `scene.json visible.user` 交集；8 张真实样本 |

**不做（v0.8）**：上传自定义壁纸、i18n、时段/日程、系统音频/Now Playing/频谱柱、性能 HUD/FPS 上限、多平台、多显示器、puppet/3D/bloom 等渲染深水区、ffmpeg 转码、Application 壁纸、场景编辑器、工坊浏览/上传。

## 3. 关键事实（本轮 spike，2026-10-19 本机库）

- 本机 workshop 共 43 个项目、37 个含 `scene.pkg`。
- **内嵌 MP4 不在 pkg 根条目里**，而是在 `.tex` 的 mip0 载荷中（`ftyp` box 位于条目头 ~91/95 字节处）。真实样本：`2911105183`（`materials/CP_ads_01.tex`，10.3MB）、`3800645169`（`materials/下载 (76)_slm_1.tex`，55.5MB）。
- 用户属性：`project.json.general.properties` 本机共 88 条（类型 bool/slider/color/combo/text），其中 **8 张 scene** 在 `scene.json` 里用 `visible.user` 绑定（如 `audiobar`/`logo`/`clouds`/`birds`）。
- 现有代码已有可复用件：`BackgroundLayer.showVideo/showSceneCanvas`、three.js `WebGLRenderer` 的 `gl.readPixels`、`RenderHealthStore`（硬/软失败记忆）、`PkgReader`、`make-tex`/`make-pkg` 测试夹具（可构造 TEXB0004 + flags bit5）。

## 4. 架构

```
host（Node/Cordis）                         client（浏览器）
├─ routes.ts                                ├─ index.ts（bootstrap/轮播/回退接线）
│  ├─ 既有 /wallpapers/*                    ├─ wallpaper-controller.ts（select + 降级决策）
│  ├─ GET /wallpapers/scene/:id/video-probe ├─ background-layer.ts（video/图片/fit/kenburns）
│  ├─ GET /wallpapers/scene/:id/embedded-video ── scene-fallback.ts（抓帧/上传/回退顺序）
│  ├─ GET|POST|DELETE /wallpapers/frame/:id  ├─ rotation.ts（轮播调度器，纯函数 + 定时器）
│  └─ GET /wallpapers/properties?id=        ├─ library-view.ts（筛选/排序纯函数）
│     ├─ scene-media-probe.ts（.tex→mp4）   ├─ local-store.ts（localStorage 封装）
│     ├─ scene-frame-store.ts（PNG 落盘）    ├─ wallpaper-properties.ts（属性读写）
│     └─ user-props.ts（project.json×scene） ├─ settings-section.tsx（新增面板区）
├─ data-dir.ts（~/.dsh-use-wallpaper）      └─ frame-export.ts（readPixels→PNG）
└─ settings.ts（新字段 schema）
```

**数据流（F1）**：scene `select` 成功 → `onSceneLive` → 若 `frameCacheEnabled` 且该 id 无帧：`renderer.captureFrame()`（readPixels→PNG）→ `POST /wallpapers/frame/<id>`（host 原子写 + 限额）→ 下次 scene 失败时按「video-probe → embedded-video → frame → preview → none」回退。

**存储模型**

| 数据 | 位置 | 理由 |
|---|---|---|
| 新增设置（fitMode / rotation* / frameCacheEnabled） | DSH host settings（`WallpaperSettingsSchema` + client DEFAULTS） | 低频配置，跟随既有双版本适配；只加标量，避免 schema 兼容风险 |
| 收藏/隐藏/最近使用 | localStorage `we:fav` / `we:hidden` / `we:recent`（JSON） | 高频交互，不写 DSH 配置；沿用 `we:userprop:` / `we:renderfail:` 既有同 origin 口径 |
| 用户属性覆盖值 | localStorage `we:userprop:<wallpaperId>:<key>`（读侧缺键回退旧全局键 `we:userprop:<key>`） | 按壁纸隔离：不同壁纸常有同名属性键（如 `newproperty1`），全局键会串值；旧键只读兼容，不再写入 |
| 抓帧 PNG | host `~/.dsh-use-wallpaper/frames/<id>.png`（env `DSH_USE_WALLPAPER_DATA_DIR` 可覆盖） | 派生缓存，需跨刷新/换端口存活；不放 DSH 配置目录，避免污染 |
| 视频解码失败记忆 | session 内存（面板状态行） | 只用于提示，不落盘；刷新可重试 |

## 5. 设计决策

**D1 降级顺序 = 实时 → 内嵌 MP4 → 抓帧 → 预览 → 空态。**
理由：MP4 是动态画面（作者原意）优先于静态抓帧；抓帧比作者 preview 更接近当前构图。替代方案「抓帧优先于 MP4」会让带内嵌视频的场景退化为静图，放弃。降级成功只代表「显示层成功」，不清 live 渲染失败记忆：软失败仍按 3s 冷却自动重试一次（每会话每壁纸一次），硬失败不自动重试。

**D2 内嵌 MP4 在 host 按需探测，不改 `/wallpapers/list` 协议。**
只读 `.tex` 头（magic + flags bit5）+ 扫描条目头 204B 找合法 `ftyp` box；按 (pkgPath, mtime) 缓存探测结果。替代方案「scanner 阶段全量扫 pkg」会让列表变慢（37 个 pkg 里最大 336MB），放弃。

**D3 抓帧只在首帧成功后一次性抓，且不影响渲染。**
`readPixels` 在 `render()` 同一 JS 任务内执行（无需 `preserveDrawingBuffer`）；编码失败/上传失败只 `console.warn`，绝不改变渲染结果；默认 `frameCacheEnabled=true`，单张 ≤12MB、目录最多 200 张（按 mtime 淘汰）。替代方案「客户端 IndexedDB 存帧」跨 origin 不共享、也绕不开容量配额，放弃。

**D4 视频兜底只做检测/提示，不做 host ffmpeg 转码。**
`showVideo` 返回 `'ok' | 'unsupported' | 'timeout'`（`error` / 1.5s 首帧超时）；失败回退预览并在面板显示「该视频编码不受支持」。转码需 ffmpeg 依赖 + CPU/磁盘 + 许可，v0.8 不引入（与产品基线报告一致）。

**D5 轮播池 = 收藏（≥2 张时）否则全部非隐藏壁纸；硬失败本会话跳过。**
不引入独立「播放列表」数据结构（v0.9 再加显式列表/导入导出）；收藏即轻量播放列表。用户手动选择重置计时；`paused` / 页面隐藏时停表；池 <2 张时显示原因而非静默。失败跳过用 `onHealth` 的硬失败标记（本会话集合），不落盘。

**D6 库管理纯前端，不改 host 列表接口。**
`filterLibrary` / `sortLibrary` 为纯函数（node 单测），UI 只依赖 `WallpaperInfo`（id/title/type/previewUrl）；收藏/隐藏/最近在 localStorage。隐藏只影响列表，不删源文件、不打断当前播放；「已隐藏」可恢复。

**D7 用户属性 v0.8 只做布尔可见性。**
只暴露「`project.json` type=bool 且 `scene.json` 中 `visible.user === key`」的属性；标签取 `text`（去 HTML），排序按 `order` 浮点；写入 `we:userprop:<wallpaperId>:<key>` 后**重选当前壁纸**才生效（装配期解析）；读侧缺 per-id 键时回退旧全局键 `we:userprop:<key>`（迁移兼容，不再写入）。slider/color/combo 需要渲染器消费对应绑定，留 v0.9；`editable:false` 丢弃；不做 localization（先用原文，v0.9 再补）。

**D8 设置字段保持标量。**
新增 `fitMode: string`、`rotationEnabled: boolean`、`rotationIntervalMs: number`（60000/300000/600000/1800000）、`rotationOrder: string`（sequential/random）、`frameCacheEnabled: boolean`；client 侧 `normalize*` 兜底未知值，沿用 `textColorMode` 的宽松 string 模式，避免 DSH 旧版 schema 拒绝。

**D9 新增监听/定时器必须走既有 teardown 路径。**
轮播定时器、抓帧 fetch、帧缓存事件全部登记到 `teardown`（`autoRetryTimers` 同款模式）；HMR 重挂载只允许存在一份。这是本仓硬约束（§5.43）。

## 6. 风险

1. **scene 切换卡顿**：轮播每次重建 player，4K 壁纸可能闪黑/卡顿；验收必须真机观察，必要时 v0.8 接受「直切」并在 README 说明，过渡动画留 v0.9。
2. **抓帧在部分 GPU/浏览器上 `readPixels` 黑帧**：用亮度/非空门禁（复用 `e2e` 已有空帧判定思路）拒绝全黑帧，失败静默。
3. **DSH settings 写入频率**：轮播只写 `selectedWallpaperId`（低频），不把计时/收藏写入 host 配置。
4. **帧缓存磁盘增长**：限额 + 淘汰；`DSH_USE_WALLPAPER_DATA_DIR` 可迁移。
5. **属性值重装配**：属性切换会触发 scene 重建（与切壁纸同成本）；面板文案要说明「切换后生效」。
6. **HMR 重挂载**：轮播/监听若未收尾会出现双定时器——单测 + dom 生命周期测试覆盖。
