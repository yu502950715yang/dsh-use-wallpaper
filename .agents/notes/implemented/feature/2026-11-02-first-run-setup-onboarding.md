# Agent Note: 首次安装的素材目录引导（首屏引导卡 + 一次性入口提示）

Status: implemented

## Problem

2026-10-19 设置页改版把「壁纸目录」折叠进底部「高级」区（见 [settings-page-redesign](../architecture/2026-10-19-settings-page-redesign.md)），代价①当时就记下了：首次配置目录要展开「高级 · 壁纸目录」。第一次安装的真实反馈是三重卡点：

1. 设置页能打开，但找不到「壁纸目录」配置（空库只提示「请在下方设置壁纸目录」，下方还有长滚动 + 折叠）；
2. 不知道要去「设置 → Wallpaper 壁纸」这个页面（装完没壁纸，也没有任何提示）；
3. 看到输入框也不知道该填什么路径（Steam workshop 目录 / 引擎目录不是用户常识）。

## Decision

**把「第一次配置」做成首屏可见的引导，而不是让用户去找折叠项；装好后主动提示一次入口。**

- **素材目录卡 = 首次引导卡（一张卡）**（`src/client/settings-section.tsx`，壁纸库 section 顶部）：
  - 空库且两个目录都没配置时默认展开，卡内顶部显示引导说明 `.wss-dirs-lead`（插件不会自己找到 Steam 里的壁纸，需要 workshop 目录 AppID 431960）；
  - 「自动探测」调现有 `/wallpapers/probe`，探测结果只在这张卡里出现一次（存在 / 不存在 + 采用）；点「采用」写设置并**自动刷新列表**；
  - 「怎么找这两个目录？」折叠帮助（Steam 库 / Wallpaper Engine 安装位置）；
  - 已配置时折叠在壁纸库底部，**不再有独立的引导卡**（第一版做成独立引导卡 + 目录卡，真机反馈是「同一件事拆成两个部分」：探测结果、输入框、帮助都出现两次 → 合并）。
- **采用后的状态同步**：`adopt` 成功后同步 `setSettings`，hint（已配置/未配置）与引导说明立即更新（此前只改输入框，真机出现「输入框已有路径、卡片仍写未配置」）；刷新后列表仍为空时明确提示「没扫描到壁纸：确认它指向 …/431960」，不静默 0 张。
- **快捷导航** 4 → 5 项（多「素材目录」，锚点指向这张卡）；空库时隐藏搜索/筛选工具栏；已配置但空库时给「目录里没有找到壁纸…点刷新」。
- **一次性入口提示条**（`src/client/setup-tip.tsx`，注册进 DSH `shell.overlay`）：未配置目录时右下角提示「打开 设置 → Wallpaper 壁纸，点自动探测」，15s 自动淡出、可「知道了」关闭；localStorage `we:setup-tip` 标记**只提示一次**；已配置或读设置失败静默不显示。样式类 `.wst-*`（只用 DSH token），渲染走 body portal + `z-index:1100`（避开 `shell.overlay` 的 z-index:20 层叠上下文，不被设置对话框遮住）。

## Affected repositories

- `dsh-use-wallpaper` 分支 `master` commits `a24b6dc`

## Alternatives considered

**只改插件描述 / README 写明入口。** 不采用：用户装插件时不会读 README，装完看不到壁纸也不会回来看文档；触达不了痛点 2。

**`settings.onboarding` 注册引导步骤 + `openSection('wallpaper-engine')` 一键跳转。** 不采用：该 slot 只在「无主会话或主会话空白」时挂载（`client-ui-settings-general` 的 `phase==='ready' && blank`），且需要自持弹窗 chrome 与完成状态；用户已有会话时不会出现，覆盖不到「第一次安装但已有会话」的主场景。

**把目录配置改成常驻 section（不再折叠）。** 不采用：已配置用户每次都要滚过两个输入框，回到 2026-10-19 改版想解决的「低频项挤占首屏」问题。默认展开只给未配置的人。

**独立「首次配置」引导卡 + 下方素材目录卡（第一版实现，已合并掉）。** 不采用：真机反馈是同一件事被拆成两个部分——探测结果、输入框、「怎么找」帮助各出现两次，点「采用」后两张卡的状态还不同步（输入框已有路径、卡片仍写「未配置」）。合并后一张卡承担引导 + 配置，`adopt` 同步 `settings`。

**侧栏常驻入口（`sidebar.footer.action` / `sidebar.toggle.badge`）。** 不采用：前者只能打开自家面板、拿不到「打开设置」能力；后者已被 DesktopUpdateBadge 占用，替换会吞掉桌面更新徽标。

## Consequences

**收益：** 空库时首屏就能完成「探测 → 采用 → 出现壁纸」，不必找折叠项；装好后有一次主动入口提示；路径怎么找从「猜」变成可展开的帮助。空库不再有搜索工具栏与重复空态。信息架构上「配置目录」只有一张卡，探测结果与输入框不再重复出现。

**代价：** ① 多一个 localStorage 键 `we:setup-tip`（提示只出现一次，忽略后不再提醒；重装同一 origin 不会重置）；② 提示条是 client DOM（portal 到 body），DSH 若改 overlay/根部样式需回归一次；③ 桌面版改动 `dist/` 后仍需重启 App 才加载新 bundle（既有规则，非本次引入）；④ 「采用」会乐观更新本地设置状态，写入失败时保留原值并在面板提示（不静默成功）。
