# Agent Note: 壁纸库默认排序收藏置顶

Status: implemented

## Problem

壁纸库网格是 372px 高的内部滚动区（3 列，一屏约 8 张），当前库数十张要滚好几屏；常看的壁纸若不在首屏，每次选图都要靠搜索或滚动重新定位。用户因此问「要不要加分页」——但列表长度本身不是瓶颈，缺的是「常看的那几张」没有稳定优先级。

## Decision

`filterLibrary` 在**默认排序**下把收藏项稳定置顶：先收藏组、再其余组，两组内部都保持入参顺序（纯分区，不改数据）；`recent` / `title` 是用户显式选择的排序，不因收藏改序；零收藏时输出与改动前逐项一致。

**不加分页、也不加虚拟滚动**：数十到数百张量级下，卡片 DOM 与 `loading="lazy"` 的图片都不是瓶颈；搜索 / 类型 / 收藏筛选已是定位手段，翻页反而让「命中结果在哪页」「当前选中 ✓ 是否可见」「N 张是全量还是本页」三件事同时变复杂。

## Affected repositories

- `dsh-use-wallpaper` 分支 `master` commits `0b135f8`

## Alternatives considered

**页码分页。** 最直观的「列表变长」解法，服务端还能只扫当前页。不用它：壁纸库是设置面板里 372px 高的选图器而不是独立页面，页码条要占掉本就紧张的可见高度；叠上搜索/类型筛选后页码要频繁重置，「第 3 页只剩 1 条」这类边界都要额外状态；选中项与计数语义也要一并拆。

**虚拟滚动。** 同样把 DOM 压到一屏量级，且不改变连续滚动与搜索体验。留到真需要时再做：当前量级的 DOM（约 400 节点）与懒加载都不构成压力，提前实现只会给筛选/排序再加一层窗口化状态。

**「所有排序下收藏都置顶」。** 让收藏永远可见。不用它：`title` / `recent` 是用户主动选择的排序，收藏置顶会把这两者的语义悄悄打断（例如按标题找某张时被收藏打乱）。

**新增「收藏优先」排序项。** 不占用默认排序的语义，表达更显式。不用它：多一个排序状态、多一个下拉项，而默认排序本来就没有用户预期要遵守的顺序，直接置顶成本更低。

## Consequences

**收益：** 常看的壁纸固定出现在首屏；零收藏的既有行为逐项不变（既有测试零改动）。

**代价：** 默认排序不再严格等于扫描顺序；收藏多到超过一屏时置顶收益递减；用户没有「纯扫描顺序」视图可切回（需要时可后续加「默认（不置顶）」选项）。
