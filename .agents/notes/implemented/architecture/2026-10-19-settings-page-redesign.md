# Agent Note: 壁纸设置页重设为 Hero + 分组 + 折叠高级区

Status: implemented

## Problem

设置页原先是由 [settings-section.tsx](../../../../src/client/settings-section.tsx) 顺序渲染的 9 张**同权重圆角卡片**：当前壁纸只是一行小字，壁纸库与目录/实时渲染/文字可读性同列，整页在 680px 宽面板里约 2100px 长滚；控件是原生 checkbox/select/range 各长各的样，深/浅色下卡片的层级也靠同一条边框区分。用户反馈「样式太丑」。

真正的问题不是缺装饰，而是**信息架构**：高频操作（选壁纸、调观感、开轮播）和低频/排障项（目录、文字可读性、实时渲染、媒体失败）没有分层，当前壁纸也没有视觉锚点。

## Decision

**Hero + 分组 + 折叠高级区，纯 CSS/DSH token，不改数据流。**

- **Hero**：用列表里已有的 `previewUrl` 渲染 16:9 预览，叠加标题、类型 badge、实时渲染状态 pill 与主操作；不发新请求、不加新状态。
- **快捷导航**：`壁纸库 / 外观 / 播放 / 高级` 四个锚点，只用 `scrollIntoView` 定位，不做 tab 状态，不改变任何控件是否挂载。
- **分组**：常用区保留单列（壁纸库 + 属性），外观与轮播在 `≥620px` 容器用 `@container` 并排、窄面板自动单列；高级区（性能与省电、文字可读性、壁纸目录、实时渲染）改为原生 `<details>` 默认折叠，保留全部控件与 ARIA。
- **控件统一**：checkbox 视觉换成 36×20 开关、range 自绘轨道与 thumb、select/input 统一 32px 高与箭头；按钮分 primary / secondary 两档。
- **视觉**：只用 `--dsw-*` / `--wp-*` 变量（深/浅色自动跟随），卡片轻边框 + Hero 轻微 accent 渐变，阴影只给 Hero；动效 150ms 且尊重 `prefers-reduced-motion`。
- **契约保持**：所有既有 `wss-*` class / `data-*` / 文案 / 行为不变，测试只新增 3 条布局用例（Hero、导航、折叠），既有 47 条 DOM 用例零改动通过。

## Affected repositories

- `dsh-use-wallpaper` 分支 `master` commits `6894e7a`

## Alternatives considered

**给设置页加 tab（壁纸库/外观/播放/高级互相切换）。** 不采用：DSH 设置对话框本身已有左侧分区，二级 tab 会再加一层层级；且 tab 需要新的激活状态与隐藏内容管理，测试与可访问性成本都更高。

**保持单列，只换配色/圆角/间距。** 不采用：这只解决「土」，解决不了 2100px 长滚、低频项挤占首屏的问题；用户最先看到的仍是「当前壁纸名字 + 一堆卡片」。

**画廊优先（壁纸大图占首屏，其余设置收进抽屉）。** 不采用：视觉冲击最强，但设置面板的主任务是「改设置」不是「逛壁纸」，且交互重构与测试改动面最大。

## Consequences

**收益：** 首屏从「一行当前壁纸」变成可见预览 + 状态 + 操作；常用项上移，高级项折叠后整页高度从约 2110px 降到约 1800px（浅/深色与窄屏实测）；开关/滑杆/下拉/按钮有统一造型与 focus ring，深/浅色只靠 DSH token，无新依赖、无新请求、无行为改动。

**代价：** ① 高级项默认折叠，首次配置目录需要展开「高级 · 壁纸目录」或看空态提示；② 外观/轮播并排依赖容器查询，极旧浏览器会退化为单列（功能不受影响）；③ Hero 预览沿用列表里的 `previewUrl`，没有预览的壁纸显示空态而非截图。
