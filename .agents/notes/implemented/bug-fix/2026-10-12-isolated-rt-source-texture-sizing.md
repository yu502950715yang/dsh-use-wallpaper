# Agent Note: 隔离对象 RT 尺寸锚在屏占位、上限取源纹理

Status: implemented

## Problem

壁纸「魔兽之门」`1922570576` 在 DSH 里比桌面 Wallpaper Engine 明显糊（用项目自己的 harness 脱离 DSH 渲染同一张壁纸，与桌面截图配准后逐块锐度比中位数 **0.54**）。

根因不是 DSH、不是 DPI 拉伸、也不是效果链本身，而是**隔离路径上对象 RT 的尺寸口径**：带 `effects` 的对象不走直渲，而是「内容 → 对象 RT → 效果链多 pass → 合成 quad → 屏幕」。本仓库把对象 RT 定为**屏占位 1×**，而桌面 WE 用的是**源纹理原生尺寸**（该壁纸源图 5000×2400 ≈ 屏占位的 2.4×）。在 1× 网格上：源图先被缩小 2.4×（削掉最高频）→ 效果链每一遍（godrays 合成、waterripple 的 UV 双线性重采样）都在这个屏幕级网格上再糊一次 → 合成 quad 又 1:1 贴回 ⇒ **模糊不可逆**。桌面在 5000×2400 上跑同一串 pass、最后只缩放到屏幕一次，单遍重采样模糊被缩小 2.4 倍，看不出来。

全库影响面：33 张 scene 壁纸里 **19 张**含带 effects 的 image 对象，共 65 个对象（其中只有 21 个铺满整屏）。

## Decision

**对每个带 `effects` 的隔离 image 对象**，把 RT 长边提到

```
targetLong = max(屏占位长边, min(源纹理长边, OBJECT_RT_MAX = 4096))     // 只升不降
RT = 世界尺寸 × (targetLong / max(|worldW|,|worldH|))，等比、按 targetLong 收口
```

配套四条不变量：

- **`max(屏占位, …)` 是不回退护栏**：源纹理比屏占位小的对象（全库 1 例）保持现状不动；返回前**逐轴** clamp 到屏占位，不能只看长轴（预算收到极限时 round 进位/舍去会让短轴少 1 px）。
- **局部正交相机的范围仍 = 未钳制的完整世界尺寸**（不动），只是像素网格变密；密度基准与主相机 cover 同源，**挂载期与 resize 期必须调同一个纯函数**。
- **MSAA 分型**：铺满整屏（world 覆盖 ≥98% 场景）⇒ `samples: 0`（RT 内只有一张盖满的 quad，没有轮廓边，实测 `samples=0` 与 `4` 逐像素完全相同 MAD=0.0000，省下的 24 B/px 用来买分辨率）；贴片与粒子 billboard 保留 `samples: 4`（有真实几何边）。
- **预算守卫**：RT 一旦大于屏占位，合成那一步就是缩小采样 ⇒ 给隔离 RT 开 `generateMipmaps + LinearMipmapLinearFilter`（RT 未放大时保持原行为）；`fitIsolatedBudget` 按每像素字节模型估算总占用，超 384 MB 预算时**等比下调升级幅度**，下限恒为各对象屏占位（最坏退回现状，不会比今天更糊）。v1 预算走常量、不新增面板设置项（避免动被测试锁定的 DOM 钩子）。

## Alternatives considered

**照 WE 口径：RT = 纹理原生尺寸、不设 4096 上限。** 理由：语义最正确 —— WE 的对象 RT 就是纹理真实尺寸，与屏幕解耦；本仓库取 1:1 只是为省显存。不用它是因为代价量级不成比例：解析估算中位 **+320 MB**、最坏 **+1797 MB**（`2597392171` 的对象 3840×6000），而 A/B 实测 4096 收口已拿到 **0.87**（桌面 = 1.00），再往上性价比极差且显存风险高。

**只提升铺满整屏的对象（立项前实验臂的口径）。** 理由：代价最小（中位 +2 MB，9/19 张变便宜或持平），且背景糊是用户看到的那个现象。不用它是因为贴片同样承担"效果链在屏幕级网格上跑"的模糊，出厂实测按逐对象口径时 **21/21 个非满屏隔离对象也被升级**（GTR 贴片 `#246` 1086×399 → 1920×705），只动满屏等于把同类缺陷留在局部对象上。

**只关 MSAA，或只优化效果链。** 理由：改动面最小，不动分辨率策略与显存。不用它是因为实测拿不回锐度：只关 MSAA 是 0.55 → **0.56**，摘掉 3 条效果链是 0.55 → **0.67**，而提到 4096 是 **0.87** ⇒ 分辨率才是决定上限的那一项。

**改纹理过滤 / 开 anisotropy。** 理由：廉价、常见的"糊"解法。不用它是因为这里的背景是一块**正对屏幕的 quad**，过滤设置不是杠杆；真正的损失来自 RT 网格密度。

**把隔离 RT 档位挂到画质档位或独立设置项。** 理由：用户可自选显存/画质权衡。不用它（v1）是因为会改动被测试锁定的设置面板 DOM 钩子（`AGENT.md` §5.39），而当前收益-风险比不支持为它改面板；预算先用常量，档位化列为后续。

## Consequences

**收益：** 5 张样本壁纸目视明显变清，全图 Laplacian 均方比 **2.39–4.03**（阈值 2.0）、逐块 96×96 中位数 **1.11–1.27**（阈值 1.05）；结构性判据逐对象独立复算通过（RT 长边 / 只升不降 / samples / mip），反向验证（撤下实现）5 张全红 ⇒ 判据真的承重。

**代价：** ① 显存代价落在"逐对象"这一档 —— 解析估算中位 **+99 MB**、最坏 **+348 MB**（±20% 量级），实测 5 张样本单张最大 ≈ 317 MB，靠 384 MB 预算守卫收窄，而**预算是软保证**（装不下全部屏占位时只能保住"只升不降"）；② RT 纹素密度变大后，**以纹素为单位的参数相对屏幕尺度变小** ⇒ 光柱/模糊观感会变（方向上更接近 WE），锐度指标测不出，本轮只目视 4 张、其余 15 张未覆盖；③ 切壁纸时新旧 RT 可能并存，峰值 ≈ 两者之和，预算护栏只约束稳态；④ 预算只覆盖 **image** 隔离对象（挂载期与 resize 期**同集合**，都是 `budgeted=image`；粒子/util/text 不参与预算所以 RT 恒按屏占位，不是 resize 误计）、视频纹理就绪前回退屏占位、精灵表按源尺寸未知处理 ⇒ 粒子与精灵表**各 0 个真实样本**，那两条只有单测；⑤ 锐度余量偏薄（最薄 1.11 vs 阈值 1.05）。

设计、全库体检与实测数据见 [隔离对象 RT 分辨率设计](../../../../docs/superpowers/specs/2026-10-12-isolated-object-rt-resolution-design.md)；这条尺寸口径已成为 `AGENT.md` §5.15 ② 的表述。
