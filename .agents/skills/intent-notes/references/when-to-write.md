# 何时写、何时就地改、何时不写

## 写

- 命中 `SKILL.md` 第一节清单的改动（判据只在那一处，别在别处复制）
- 一个理由被解释了第二遍——那就该写下来了
- 拍板了一条路线："就选 X"、"决定用 X"
- 比较中："X 和 Y 怎么选"——此时备选方案还在手上，是记录成本最低的时刻
- 看着像机械改动、实则定了新契约（新建类型 / 字段集 / 接口形状，或引入 / 移除第三方依赖）——见 `SKILL.md` 第一节的"看着像机械、其实是契约决策"

## 就地改（不要新开一篇）

在**持有该决定**的旧笔记里修正事实：代码路径、方法签名、默认值、模块名。**核心理由不变**时一律就地改，不要追加变更流水账。

## 新开一篇

决定本身或理由翻转了 → 新开一篇，两篇互链，并处理旧篇（见 `archiving.md`）。**一条笔记永远不被改写成另一个决定。**

## 不写

`SKILL.md` 第一节的机械改动清单。列在这里的每一条，都**不要**给它开笔记——尤其"照已有契约的常规 CRUD"：照现有类型与接口写就不写，而新建类型 / 字段 / 接口形状是契约决策，要写（判据见 `SKILL.md` 第一节）。

## 新建前的固定动作

见 `SKILL.md` 硬规则 9：搜同主题旧笔记并当场分类（无关 / 部分重叠 / 完全吸收 / 过时），分类结果与新笔记一起落盘。判据只写在硬规则 9 一处，本文件不复述。
